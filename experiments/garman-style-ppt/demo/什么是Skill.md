# 什么是 Skill

一份写给初次接触者的说明

## 一、一句话定义

Skill 是一个文件夹，里面装着完成某类任务所需的说明、脚本和参考资料。智能体在需要时读取它，就像新同事翻开一本岗位手册。

Skill 不是新模型，也不是插件程序，而是把经验写成文字，让通用智能体变成某件事的熟手。

## 二、一个 Skill 里有什么

SKILL.md：必需的说明书。开头用几行元数据写明名称和用途，正文写步骤、规则和示例。

scripts：可选的脚本。确定性的工作交给代码完成，比让模型临场发挥更稳定。

references：可选的参考资料。篇幅较长的规范、表格放在这里，用到时再读。

assets：可选的素材。模板、字体、图片等直接拿来用的文件。

## 三、它是怎么工作的

第一步，启动时只读名称和描述：每个 Skill 只占几十个词，装上一百个也不拥挤。

第二步，判断相关：用户的请求和某个描述对上了，智能体决定启用这个 Skill。

第三步，读取正文：把 SKILL.md 的全部说明读进来，照着步骤做。

第四步，按需深入：遇到具体问题，再去读对应的参考文件或运行脚本。

这种做法叫「渐进式披露」：先看目录，再翻章节，用多少读多少。

## 四、几个关键数字

名称最长 64 个字符，只用小写字母、数字和连字符。

描述最长 1024 个字符，要同时写清“做什么”和“什么时候用”。

SKILL.md 正文建议控制在 500 行以内，更长的内容拆到参考文件里。

## 五、Skill 和提示词有什么不同

提示词：每次对话都要重新粘贴，写在聊天里，用完就散，难以分享和维护。

Skill：写一次、反复用，以文件形式保存，可以版本管理，也可以打包分享给团队。

提示词适合一次性的临时要求，Skill 适合反复出现、需要稳定质量的工作。

## 六、一个例子：GarmanPPT

GarmanPPT 就是一个 Skill：用户交来定稿文档，智能体按说明分页，再由脚本生成可编辑的 PPT。

它的说明书规定了四条铁律：只摘不写、原文一段不丢、以脚本校验为准、不改脚本。

你现在看到的这份演示文稿，就是用它的实验版生成的。

## 七、写好一个 Skill 的要点

描述要具体：写清触发场景，智能体才知道什么时候该用它。

步骤要可执行：像写给新同事的操作手册，而不是一篇论文。

能用脚本的不靠模型：校验、计算、格式转换交给代码。

一句话总结：Skill 把“会做”变成“稳定地做好”。
